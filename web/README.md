# مصباح الصادقین — نسخهٔ وب (PWA)

نسخهٔ وبِ قابل نصبِ برنامهٔ «مصباح الصادقین» (انیس الصادقین و سفینة الصادقین) برای آیفون، اندروید و رایانه.
پس از اولین بازدید، همهٔ کتاب‌ها و قلم‌ها در گوشی ذخیره می‌شوند و برنامه **بدون اینترنت** هم کار می‌کند.
کاربران آیفون از Safari با «Add to Home Screen» آن را مثل یک برنامه روی صفحهٔ اصلی نصب می‌کنند.

امکانات همان برنامهٔ اندروید است: فهرست مطالب درختی، صفحهٔ مطالعه با ورق زدن (کشیدن انگشت) و دکمه‌های قبلی/بعدی،
نمایش جداگانهٔ متن عربی، ترجمه، توضیح و پاورقی، تنظیمات متن (پوسته، قلم، اندازه، فاصلهٔ سطر)، جستجوی کامل
بدون حساسیت به اعراب و «ی/ي»، «منتخب من» و خواندن پشت‌سرهم، نشانه‌ها با یادداشت، ادامهٔ مطالعه و پرکاربردها،
و پیوند مستقیم به هر دعا (مثلاً `https://دامنه/#/r/1/10`) برای اشتراک در کانال ایتا.

---

## پیش‌نیاز

- **Node.js نسخهٔ ۲۲٫۱۸ یا جدیدتر** (فقط برای ساختن؛ سایت نهایی فایل‌های ایستاست و روی هاست به Node نیاز ندارد).
- یک بار در همین پوشه: `npm install`

## دستورها

| دستور | کار |
| --- | --- |
| `npm run build` | داده‌ها را از فایل‌های `.book` می‌سازد و سایت کامل را در پوشهٔ `dist/` تحویل می‌دهد. |
| `npm run build:web` | همان، ولی بدون ساختن دوبارهٔ داده‌ها (از داده‌های موجود در `public/data` استفاده می‌کند). |
| `npm run data` | فقط داده‌ها را از فایل‌های `.book` می‌سازد. |
| `npm run dev` | اجرای آزمایشی هنگام برنامه‌نویسی (`http://localhost:5173`). |
| `npm run preview` | نمایش خروجی ساخته‌شده (`dist/`) روی `http://localhost:4173` برای آزمایش پیش از انتشار. |

## به‌روزرسانی متن کتاب‌ها (فایل‌های `.book` جدید)

۱. فایل‌های جدید را با همان نام‌ها در پوشهٔ `New folder/Files/` جایگزین کنید:

| فایل | کتاب |
| --- | --- |
| `1.book` | انیس الصادقین (متن عربی بند به بند، هر بند با ترجمه‌اش) |
| `4.book` | انیس الصادقین بدون ترجمه — فقط برای پاراگراف‌بندی (توضیح پایین) |
| `3.book` | سفینة الصادقین — فارسی |
| `2.book` | سفینة الصادقین — عربی |

**انیس الصادقین یک کتاب است با کلید «با ترجمه / بدون ترجمه».** متن برنامه همیشه از `1.book` خوانده می‌شود. وقتی
ترجمه خاموش است، تکه‌های عربیِ پشت‌سرهم به هم می‌چسبند و پاراگراف‌های پیوسته می‌شوند؛ جای شکستن پاراگراف‌ها از
`4.book` برداشته می‌شود (با پیدا کردن حروف اطراف هر شکستگی در `1.book`)، بی‌آنکه حتی یک کلمه از متن تغییر کند.
اسکریپت ساخت در گزارش خود تعداد پاراگراف‌ها و شکستگی‌های پیداشده را چاپ می‌کند. با
`SHOW_LOST_BREAKS=1 npm run data` شکستگی‌هایی که پیدا نشدند (معمولاً جاهایی که متن دو نسخه با هم فرق دارد) فهرست می‌شوند.

۲. (اختیاری) شمارهٔ نسخه را در `package.json` (فیلد `version`، مثلاً `1.0.1`) بالا ببرید تا در برنامه نمایش داده شود.

۳. دستور `npm run build` را اجرا کنید. خروجی در پوشهٔ `dist/` است. در گزارش دستور، تعداد بخش‌ها و بندهای هر کتاب
چاپ می‌شود تا از درستی تبدیل مطمئن شوید.

اگر فایل‌ها جای دیگری هستند: `npm run data -- --src "مسیر/پوشه"` و سپس `npm run build:web`.

۴. پوشهٔ `dist/` را منتشر کنید (پایین‌تر). کاربرانی که برنامه را نصب کرده‌اند، در بازدید بعدی پیام
«نسخهٔ تازهٔ برنامه آماده است» را می‌بینند؛ فقط فایل‌هایی که واقعاً تغییر کرده‌اند دوباره دریافت می‌شوند.

**چه اتفاقی می‌افتد؟** فایل‌های `.book` پایگاه‌دادهٔ SQLite هستند که همهٔ بایت‌هایشان با `0xFF` رمز (XOR) شده‌اند.
اسکریپت `scripts/build-data.ts` (فقط با Node، بدون نیاز به ابزار دیگر) آن‌ها را باز می‌کند، همان قواعد برنامهٔ اندروید
را برای تشخیص عنوان، متن عربی، ترجمه، توضیح، پاورقی و شمارهٔ صفحه به کار می‌برد، و خروجی را این‌طور می‌نویسد:

- `public/data/<شمارهٔ کتاب>/toc.*.json` — فهرست مطالب
- `public/data/<شمارهٔ کتاب>/c*.json` — متن بخش‌ها در تکه‌های حدوداً ۱۰۰ کیلوبایتی
- `public/data/<شمارهٔ کتاب>/search.*.json` — متن یکسان‌شده (بدون اعراب، «ي←ی»، «ك←ک» و …) برای جستجو
- `src/generated/data-manifest.json` — نشانی فایل‌های بالا برای برنامه

نام فایل‌ها شامل اثرِ محتوا (hash) است؛ بنابراین هیچ مرورگر یا CDNی نسخهٔ کهنه را نشان نمی‌دهد.

## انتشار روی هاست

سایت فقط از فایل‌های ایستا تشکیل شده است: **محتوای پوشهٔ `dist/`** را در ریشهٔ دامنه یا زیردامنه بارگذاری کنید
(مثلاً `https://app.example.ir/`). برنامه هیچ درخواستی به سرور دیگری نمی‌فرستد.

نکته‌های لازم:

- **HTTPS الزامی است.** نصب روی گوشی و کار بدون اینترنت (Service Worker) فقط روی HTTPS فعال می‌شود.
- برنامه برای **ریشهٔ دامنه** ساخته می‌شود. اگر بخواهید در زیرپوشه (مثلاً `/mesbah/`) منتشر کنید، مقدار `base` را در
  `vite.config.ts` به `'/mesbah/'` تغییر دهید و در `public/manifest.webmanifest` مقادیر `id`، `start_url`، `scope` و نشانی
  آیکون‌ها را هم به همان مسیر تغییر دهید، سپس دوباره بسازید.
- این سه فایل نباید طولانی‌مدت در حافظهٔ موقت (cache) نگه داشته شوند: `index.html`، `sw.js`، `manifest.webmanifest`
  (`Cache-Control: no-cache`). فایل‌های `assets/*` و `data/*` نامِ یکتا دارند و می‌توانند یک سال cache شوند.
- فشرده‌سازی gzip/brotli را برای `json`، `js`، `css` و `html` روشن کنید: حجم داده‌ها از حدود ۱۴ مگابایت به حدود ۳٫۶ مگابایت
  می‌رسد.
- نسخهٔ اندروید (APK) در نشانی `/download/mesbah-sadeghin.apk` انتظار می‌رود؛ آن را کنار سایت در پوشهٔ `download/`
  قرار دهید. دکمهٔ «دانلود نسخهٔ اندروید» فقط در گوشی‌های اندروید نشان داده می‌شود و این فایل در حافظهٔ آفلاین ذخیره نمی‌شود.

### نسخهٔ آزمایشی روی GitHub Pages

با هر push به شاخهٔ `main` که `web/` یا فایل‌های `.book` را تغییر دهد، گردش‌کار
[`pages.yml`](../.github/workflows/pages.yml) برنامه را می‌سازد و در `https://taher31.github.io/Mesbah-al-Sadeghin/`
منتشر می‌کند (برای آزمایش روی آیفون و گوشی‌های دیگر). در این حالت برنامه برای زیرمسیر `/Mesbah-al-Sadeghin/` ساخته
می‌شود: `BASE_PATH=/Mesbah-al-Sadeghin/ npm run build`. پیکربندی یک‌باره: Settings › Pages › Source: «GitHub Actions».

### هاست cPanel (Apache)

فایل `.htaccess` همراه خروجی است و همهٔ موارد بالا را تنظیم می‌کند: انتقال به HTTPS، نوع فایل‌های `webmanifest` و `apk`،
cache مناسب و فشرده‌سازی. فقط مطمئن شوید هنگام بارگذاری، فایل‌های مخفی (که با نقطه شروع می‌شوند) هم منتقل شوند.

### ابر آروان (ArvanCloud)

- **فضای ابری (Object Storage) با وب‌سایت ایستا:** محتوای `dist/` را در یک bucket بارگذاری کنید، «میزبانی وب‌سایت ایستا»
  را با سند پیش‌فرض `index.html` روشن کنید و دامنه را متصل کنید. برای `index.html`، `sw.js` و `manifest.webmanifest`
  سرآیند `Cache-Control: no-cache` و برای `manifest.webmanifest` نوع `application/manifest+json` تعیین کنید.
- **CDN آروان جلوی هاست اصلی:** HTTPS را فعال کنید، در قواعد cache گزینهٔ «پیروی از سرآیندهای سرور مبدأ» را انتخاب کنید
  (یا برای سه فایلِ گفته‌شده cache را خاموش کنید)، و فشرده‌سازی را روشن کنید.

### Nginx (در صورت نیاز)

```nginx
location = /index.html { add_header Cache-Control "no-cache"; }
location = /sw.js { add_header Cache-Control "no-cache"; }
location = /manifest.webmanifest { add_header Cache-Control "no-cache"; types { application/manifest+json webmanifest; } }
location ~ ^/(assets|data)/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
gzip on; gzip_types application/json application/javascript text/css application/manifest+json;
```

## آزمایش پیش از انتشار

۱. `npm run build` و سپس `npm run preview`، و نشانی `http://localhost:4173` را در Chrome یا Edge باز کنید.
۲. پایین صفحهٔ اصلی باید پس از چند لحظه «همهٔ کتاب‌ها برای استفادهٔ بدون اینترنت آماده است» نوشته شود.
۳. سرور را ببندید (یا در DevTools حالت Offline را بزنید) و صفحه را دوباره بارگذاری کنید؛ کتاب‌ها و جستجو باید کار کنند.

(روی گوشی از راه شبکهٔ محلی با `http://` حالت آفلاین فعال نمی‌شود، چون مرورگرها Service Worker را فقط روی HTTPS یا
`localhost` اجرا می‌کنند. آزمایش روی گوشی را روی نشانی HTTPS انجام دهید.)

## راهنمای کاربران آیفون

۱. سایت را در **Safari** باز کنند (در مرورگر داخلی ایتا امکان نصب نیست؛ از منوی صفحه «باز کردن در Safari» را بزنند).
۲. دکمهٔ اشتراک‌گذاری (مربع با پیکان رو به بالا؛ در iOS ۲۶ ابتدا دکمهٔ «⋯») ← **Add to Home Screen** ← **Add**.
۳. برنامه را یک بار با اینترنت از صفحهٔ اصلی باز کنند تا کتاب‌ها ذخیره شوند.

خود برنامه هم این راهنما را در Safari آیفون (و راهنمای «در Safari باز کنید» را در مرورگرهای داخلی) نشان می‌دهد.

**دادهٔ کاربران:** منتخب‌ها، نشانه‌ها، یادداشت‌ها، جای مطالعه و تنظیمات در خود مرورگر ذخیره می‌شوند. در آیفون، برنامهٔ
نصب‌شده روی صفحهٔ اصلی فضای جدایی از Safari دارد؛ برای انتقال داده بین آن‌ها یا به گوشی دیگر از
«تنظیمات ← پشتیبان‌گیری از داده‌های من» استفاده کنید (ذخیره و بازیابی فایل پشتیبان؛ بازیابی چیزی را پاک نمی‌کند).

## ساختار پوشه

```
web/
├── index.html                صفحهٔ اصلی و برچسب‌های iOS
├── vite.config.ts            ساخت؛ تولید sw.js با فهرست همهٔ فایل‌ها
├── sw/sw.template.js         Service Worker (حافظهٔ آفلاین، به‌روزرسانی)
├── scripts/
│   ├── build-data.ts         تبدیل فایل‌های .book به JSON (فقط Node)
│   ├── convert-fonts.mjs     تبدیل یک‌بارهٔ قلم‌های TTF برنامهٔ اندروید به WOFF2
│   └── prepare-images.py     ساخت یک‌بارهٔ آیکون‌ها و تصاویر (Python + Pillow)
├── public/                   فایل‌هایی که عیناً در خروجی کپی می‌شوند
│   ├── data/                 داده‌های ساخته‌شدهٔ کتاب‌ها
│   ├── fonts/  img/  icons/  قلم‌ها، تصاویر و آیکون‌ها
│   ├── manifest.webmanifest
│   └── .htaccess
└── src/
    ├── lib/                  داده، جستجو، ذخیرهٔ کاربر، مسیریابی، PWA
    ├── screens/              صفحه‌ها (خانه، فهرست، مطالعه، جستجو، …)
    ├── ui/                   اجزای مشترک
    └── styles/               رنگ‌ها و چیدمان (روشن، کاغذی، شب)
```

قلم‌ها و تصاویر یک بار از منابع برنامهٔ اندروید ساخته شده‌اند و در `public/` قرار دارند؛ برای ساختن دوباره (فقط اگر
تغییر کرده باشند): `npm run assets` (به Python و Pillow نیاز دارد).

قواعد تبدیل متن و یکسان‌سازی حروف برای جستجو (`src/lib/normalize.ts`) با برنامهٔ اندروید (`TextNormalizer.kt`) یکی است؛
اگر یکی تغییر کرد، دیگری را هم هماهنگ کنید.
